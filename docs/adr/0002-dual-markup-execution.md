# 标记语言支持编译与可选运行时加载

用户在 Q4 选择构建期编译与独立可选的运行时加载：普通应用可省去发布时的标记解析和执行依赖，Quickshell 类宿主则可直接加载界面配置。代价是需要定义两条路径一致的界面语义与诊断规则；运行时加载不能成为命令式 API 或编译产物的强制依赖。

本决定不选择具体语法、编译产物格式、热重载机制或脚本引擎；它们将在相同语义约束下继续选型。

## 实现补充

静态文档编译为直接构造，不依赖运行时引擎。含 state、绑定、事件块、if/for、组件或导入的文档在构建期解析并检查，生成构造已检查程序的 Rust 代码，再由可选 `aegle-loader` 引擎执行；这类发布产物携带执行引擎，但不携带解析器或检查器。运行时加载复用同一解析、检查与诊断规则后交给同一引擎，因此两条路径共用一套执行语义，而不是维护两套实现。

静态文档的直接构造与引擎仍是两份代码，靠以下约定保持一致：检查规则只在 `aegle-markup` 中（含 id 与 state 重名），宏与运行时加载不另加规则；构建顺序相同（先创建本次构建的全部控件，再按文档顺序设置属性，最后安装过渡与事件）；枚举标识符以 `choices` 为唯一来源，宏按名称生成变体，引擎逐项映射而无默认分支；层数上限由 `Limits` 的 `max_depth`（不超过 `Limits::MAX_DEPTH`）统一约束组件、表达式嵌套与运算符/字段链；类型不允许 `list` 嵌套，故无递归。`Program::from_checked` 只供生成代码传入构建期检查过的程序，文档隐藏。facade 的 `tests/paths.rs` 用同一文档对照两条路径的全部绘制记录与过渡时序，并检查文档覆盖每个可用的 `choices` 值。
