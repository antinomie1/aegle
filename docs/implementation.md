# 实现状态

完整目标保持不变：模块化保留模式 GUI、GPU 与无 GPU 软件绘制、CJK/原生 IME、无障碍、组件/主题/动画、命令式与标记入口、跨平台及 API 文档。

## 已实现

- Rust 2024 workspace，MIT OR Apache-2.0；目标 MSRV 1.88，Linux 验证工具链为 1.96.1，Windows 为 1.99.0；MSRV 1.88 曾在 Windows 上（2026-10-08，TSF 改动之前） `cargo check --workspace --all-features`（不含仅限 Linux 的 Wayland crate）通过。
- aegle-types：no_std 几何与紧凑 RGBA 颜色，无第三方依赖。
- aegle-core：代数 ID、可复用槽位、保留树、索引子节点、结构变更与三通道失效，另有路由快照、默认动作控制及策略化焦点遍历；无第三方依赖。叶节点不分配子节点数组，删除不递归。
- aegle-layout：Taffy 0.14.0 直接适配同一棵保留树，无第二份拓扑；共享默认样式、测量缓存、Flex/Block、可选 Grid。它不依赖字体、窗口或 renderer。滚动的一轴（`Overflow::Scroll`、无确定尺寸）在最小内容约束下只量出内边距、边框与最小尺寸，沿主轴滚动的 flex 容器的子项不收缩：ScrollView/ListView/表格及其各层祖先因此收缩到窗口给的空间而不被内容撑开，不再需要在中间容器上写 `min_height: 0`；ScrollView 去掉了 `flex_shrink: 0`，文本框横向可收缩；标签栏放不下时换行，图像在可用宽度小于像素宽度时按宽高比缩小（`composite.rs` 的 `tab_bars_and_images_fit_a_narrow_window` 在 200 宽窗口中断言六个标签与 400×100 图像都在窗口内）。浮层同样不越出窗口：Popup（含 Dropdown 列表与菜单）至多与窗口同宽同高、是可滚动视口，上下都放不下时贴窗口边缘；Dialog 卡片与遮罩边缘留 16，打开时由 widgets 的 measure 钩子把 320 的最小宽度降到遮罩可用宽度，卡片与 Drawer 面板（宽度上限为覆盖区域）在内容放不下时滚动；Slider/Progress 不再 `flex_shrink: 0`，沿轴向最小尺寸为 0、厚度方向以主题高度为最小值（与文本框一样，`set_min_height` 可覆盖），窄行中收缩；被压到比步进区还窄的 NumberField 绘制时不再因负宽裁剪而 panic。验证：`aegle-widgets/tests/fit.rs` 在 220×200 窗口中断言 40 项弹出列表、20 行正文的对话框（卡片宽 188）与 20 项抽屉都在窗口内且可滚动，窄行中的 Slider/Progress/文本框/NumberField 不超出窗口、拥挤列中 Slider/Progress 保持 32/16 高；改动前弹出层断言失败，去掉 NumberField 的修正则该测试 panic。showcase 示例的控件行改为换行、两个列表 `set_basis(0.0)` 平分一行、左栏与 Views 页放入无边框 ScrollView：按其结构的无窗口探测（软件绘制截图并遍历节点边界）在 320–960 宽、160–720 高的窗口中没有控件越出所在窗格（更窄时仅剩无法换行的复选框标签，可在左栏中横向滚动到达）；该探测是临时脚本，未进入测试。gallery 参考图重新生成后像素不变。验证：`aegle-widgets/tests/scrolling.rs` 的 `scroll_views_fit_the_window_and_their_content_scrolls` 以“列 > 标签页 > 页 > 行 > ScrollView(grow)”与“页 > ScrollView”两种结构（均无 min_height）断言视图不超出 240 高的窗口且可滚动、视图内多行文本框保持 128 高、窄行中文本框收缩使按钮留在窗口内；改动前该测试与 `composite.rs` 去掉 `set_min_height(0.0)` 的表格测试均失败。
- aegle-scene：no_std + alloc 的局部绘制记录；实色矩形、圆角、居中边框、共享 RGBA 图像、填充/描边路径、仿射变换、嵌套裁剪，以及供 renderer 使用的图层描述 `Layer` 与模糊盒计划。可选 text 保存定位字形、变体坐标与共享字体句柄，不依赖排版器或栅格器。
- 系统文字栈（2026-11-02）：排版与字形默认改为操作系统的文字栈，`aegle-text` 新增 `layout.rs`（`PlatformSystem`/`Layout` 分派点）与 `backend_pango/`（`sys` 里的 C 接口与运行时加载、`system` 里的 fontmap/Fontconfig 配置与 generic family 映射、`layout` 里的成形与尺寸、`metrics` 里的行度量/命中/光标/范围/分段/诊断、`paint` 里的字形记录与场景输出），`aegle-glyph` 新增 `freetype.rs`。Linux 上 `libpango-1.0.so.0`、`libpangoft2-1.0.so.0`、`libgobject-2.0.so.0`、`libfontconfig.so.1`、`libfreetype.so.6` 全部用 libloading 打开，缺失即如实不可用；`FcInit` 只做一次，`TextSystem::new()` 给出空 FcConfig 只含注册字体，`TextSystem::system()` 用发行版配置。`text-parley`/`swash` 降级为默认关闭、不再维护的回退，`desktop` 不再含 `colrv1`（FreeType 的 `FT_LOAD_COLOR` 已覆盖 COLR 与内嵌位图）。证据：`cargo test --workspace` 162 个测试二进制、164 项通过；`cargo clippy --workspace --all-targets` 与 `cargo fmt --check` 无告警；`cargo test -p aegle-text --features text-parley,text-a11y,scene` 同样通过（回退路径仍可编译）。视觉核对用系统字体渲染中文/日文/韩文/拉丁混排、220/240/300 像素换行的段落、2.0× 与 1.2× 行距，以及带选择的编辑器，均正确分行、行距与字形一致；同一画面在真实 Plasma Wayland 会话的运行窗口中复现（`hello`/`controls` 均正常显示）。Linux 默认 feature 的 `hello` 从 4,891,328 B 降到 2,580,056 B。修复的三个系统栈行为：行 extents 的 y 是相对基线而不是布局顶端（导致多个硬换行段落重叠绘制）、`pango_layout_set_line_spacing` 的因子是"行高倍数"而不是"额外比例"、`pango_layout_xy_to_index`/`move_cursor_visually` 的 `trailing` 表示"落在字符后半"而不是"加一个字节"（后者会把半个 UTF-8 字符当作光标偏移，宿主发布 IME surrounding 时触发 `InvalidIme`）。缺字时 Pango 自己画占位框，Aegle 不再改画 `.notdef` 并与 advance 保持一致。未完成：Windows 的 DirectWrite 与 macOS 的 CoreText 后端仍走回退，Windows 目标尚未重新测量发布文件。

- aegle-text：默认把 Unicode shaping、字体选择、回退、换行与定位交给平台系统栈（见上一条），`text-parley` 下则复用 Parley/Fontique；Paragraph 保留文字、排版结果及去色的 shaping 键（字体族名由 TextSystem 驻留共享），宽度变化只重排，只改颜色的 `restyle`/`update` 不重新 shaping；`release` 释放排版、保留文字/样式/宽度/内容宽度，`TextSystem::restore` 重新成形，共享 TextSystem 上的空闲文字预算见下文。显式字体为默认，system-fonts、text-a11y、scene 独立选用；缺字与无可用字体分别报告。按词移动与双击选词不再用 Parley 的 complex-scripts 词典数据，而是取 `aegle-segment` 从系统分词器得到的边界（见下一条），没有系统分词器时这两个操作停用，不保留近似分词。
- Editor：复用同一 TextSystem 的字形系统与 `Layout` 的段落排版（`text-parley` 下即 Parley 的 `Cursor`/`Selection`），不再包装 PlainEditor：文字按硬换行分成段落块，每块一个排版结果（连同其后的换行符成形，语义 run 与选区几何与整段布局相同，排版时跳过换行后的空行），编辑只重新成形触及的段落及被合并或拆开的相邻段落，改宽度/对齐只重新断行，只改颜色不成形（`EditChanges::paint`）；移动、命中与选择在块内用 `Layout`、跨块时走到相邻块，`Editor::layouts` 给出各块布局与原点。提供单/多行、选择/命中、视觉移动、grapheme 删除、精确 UTF-8 替换、只读、组合输入模型及有界差量撤销/重做。预编辑只保留被替换片段，提交值不随预编辑改变；取消恢复原选区。文字、装饰和候选区域来自同一布局。密码模式只排版等量 `•`，明文另存且不记录历史、拒绝 IME 组合。apply_ime 在完整验证后应用删除/提交/预编辑事务，删除与提交合成一次撤销；surrounding 无分配地借出有界周边文字；grapheme 删除只分段光标所在的一行。`cargo run -p aegle-text --release --example large_document`（2,000 行、约 120 KB 混排文字，宽 400 逻辑像素换行，Windows 11/i5-13600KF）：改造前（PlainEditor）在中间输入一个字符 18.2 ms、改宽度 18.2 ms、只改颜色 18.1 ms，改造后分别为 22 µs、0.62 ms、20 ns，打开并换行 37 ms → 23 ms；`aegle-text/tests/document.rs` 检查任意编辑序列（行内输入、拆行、退格合并行、`\r` 与 `\n` 合并为 CRLF、跨行删除与撤销/重做）后的尺寸、光标与选区几何都等于由同一文字新建的编辑器，并覆盖跨行的方向键与命中。字体或字号改变仍重新成形全部段落；单行编辑器只有一个段落，每次编辑仍重新成形整行。
- aegle-controls：共享无分配 Range、Toggle、Slider 和无皮肤 Button 的键盘/指针/语义激活、capture 和取消状态；可选 text 提供复用 Editor 的 TextField。宿主拥有树、命中和焦点；controls 默认只依赖 types，不依赖窗口或 renderer。
- aegle-access：平台回调经 Mailbox/Handlers 排队并唤醒 UI；可选 UnixAdapter/WindowsAdapter/MacosAdapter 复用 AccessKit AT-SPI/UIA/NSAccessibility。示例从同一控件树按脏标记导出语义，系统 Focus/Click/SetTextSelection 回到同一焦点、按钮和 Editor。text-a11y 提供文字 run 与有校验的选择转换；不是完整跨平台无障碍。
- aegle-glyph：复用 Swash/Skrifa，按需生成灰度字形与 COLRv0/嵌入位图，LRU 同时约束图像字节和条目数；缓存不持有字体文件。PNG 位图使用有解码预算的 png crate；库不内嵌字体。
- aegle-render-software：借用 RGBA8 缓冲，tiny-skia 负责抗锯齿覆盖率，线性光 SourceOver 合成器处理透明颜色。默认仅几何；可选 text 接同一 Scene 的字形、变换和裁剪。支持均匀缩放的四分之一像素定位及任意可逆仿射变换的双线性采样，无裁剪文字无需面大小的 mask。
- aegle-render-vulkan：独立 Vulkan 1.1 离屏绘制，复用 Scene；GPU 绘制矩形/圆角/居中边框、仿射变换及最多八层裁剪，可选 text 接有界按需灰度/彩色字形图集。RGBA16F 线性混合后由第二遍 GPU 编码预乘 sRGB RGBA8；显式读回、有界设备/记录分配和单次在途提交。已验证硬件与软件 ICD；可选 window 已提供原生 swapchain，App 可显式选择。
- 图层：`Node::set_opacity`（可过渡）与 `set_backdrop_blur` 让子树经 `Visit::PushLayer`/`PopLayer` 在离屏层中绘制，软件、Vulkan 与 wgpu 的 `Frame::push_layer`/`pop_layer` 实现同一合成与三次盒式模糊（见[平台与绘制](platform-rendering.md#图层)）；GPU 后端需要 `text`。组效果损伤整个子树，背景模糊在损伤触及采样区时整体重绘。原生 App 与 gallery 宿主已转发图层。
- 阴影与渐变：`TransitionProperty::Shadow` 补间阴影的偏移、模糊、扩展与颜色（出现/消失按颜色淡入淡出），接入 `with_transition`/`snap`、减少动态效果与完成回调；`Shadow` 移到 `aegle-types` 并成为 token 类型（`bind_shadow`），渐变色标经 `ColorSlot::GradientStop(i)` 跟随颜色 token。背景渐变随 `TransitionProperty::Paint` 补间（`aegle-ui/src/gradient.rs`）：色标与几何从当前呈现的渐变出发，出现与消失从/到背景色，色标数不同时短的一方重复末尾色标，线性渐变按中心、方向与半长补间（不会退化），线性与径向互换时几何立即取目标、色标补间；采样经新增的 `Gradient::update` 写回节点渐变，两份色标存储逐帧交替（上一帧的记录仍共享另一份），`aegle-ui/tests/gradient.rs` 以计数分配器测得补间中五帧推进加刷新 0 次分配，并检查方向转动、结束时等于目标与淡出后移除。标记节点属性 `shadow`、`background_gradient`、`opacity`、`backdrop_blur`、`shadow_transition`、`opacity_transition` 在 `ui!` 与运行时引擎中都经 loader 的同一组 setter 应用，`aegle/tests/effects.rs` 以同一文档比较两条路径并检查主题切换后的 token 跟随；`aegle-ui/tests/effects.rs` 检查阴影淡入、中途改目标、结束与淡出移除。加入后 1000 控件场景不变：首帧 3.05–3.10 ms/12,253 次分配，空闲 22 µs/4 次，改值 22 µs/4 次，悬停 31 µs/7 次。
- 捕获与冒泡：`Node::on_input_capture` 与 `Node::on_input` 登记的监听器收到 `InputEvent`（`InputKind::Pointer`/`Key`/`Wheel`、路由目标 `target`、`phase()` 为 Capture/Target/Bubble），输入从根向下经捕获监听器到目标、再向上经冒泡监听器，之后才交给引擎与目标控件；指针的目标是捕获者或指针下最上层的节点，按键是焦点控件（没有时为根，排在 `Ui::on_key` 之后），滚轮是指针下的节点。`stop_propagation` 在当前节点的监听器之后结束路径，`prevent_default` 跳过默认行为（指针交给控件及其双击/上下文菜单、按键的控件库键绑定/Tab 遍历/焦点控件、滚动；悬停仍跟随指针）。监听器在所有 UI 借用之外运行，可增删控件；出错不阻止默认行为，首个错误由输入调用返回。没有任何监听器时路由不计算路径、不分配（`aegle-widgets/tests/propagation.rs` 覆盖顺序、停止、阻止指针与按键默认行为）。
- 可移除的处理器：所有 `on_*`（`on_action` 与各控件的 `on_click`/`on_change`/`on_submit`、`on_double_click`、`on_context_menu`、`on_drop`、`on_transition_end`、`on_frame`、`Ui::on_key`、`on_input`/`on_input_capture`）返回 `Subscription`，`remove()` 后处理器不再运行，包括同一事件正在派发、尚未轮到它时；重复移除或控件/窗口已不在时无操作。每个回调各占一个带序号的槽位，运行时槽位暂空、结束后按序号放回，因此派发中移除无需另记待删列表，派发中新增的处理器从下一次事件起运行（`propagation.rs` 覆盖派发中移除自己与后续处理器、按键与逐帧回调的移除）。`element!` 的事件胶水接受返回任意值的注册闭包。
- 空闲文字预算：`TextSystem::set_idle_budget(bytes)`（默认 `None`，不回收）限制共享同一 TextSystem 的全部窗口中未显示、仍保留排版的段落文字字节数（计的是 UTF-8 字节，不是排版分配）。每个 Ui 在刷新末尾按 `visit_scenes` 的同一可见判定扫描文字控件：显示中的记下时间，已释放又重新显示的重新成形、按最终宽度重排并录制；未显示的上报给 TextSystem，总量超出预算时由正在刷新的窗口按最久未显示先释放自己的段落排版与绘制记录（`Control::paragraph_mut` 的主段落；菜单项的快捷键提示等附加段落不回收），直到总量回到预算内。被释放的段落在 Taffy 测量或求基线前重新成形，`finalize` 与重新录制推迟到再次显示，主题与文字变化只记下样式与文字。未刷新的窗口不回收，关闭或销毁的 Ui 撤回上报。编辑器保留活动编辑状态，不参与回收。`aegle-widgets/tests/idle.rs` 用两个共享 TextSystem 的 Ui 检查跨窗口的总量、释放顺序、重新显示后绘制字形与撤回上报。代价：被释放的段落每次参与重新布局（窗口缩放、内容变化）都要重新成形，刷新末尾的扫描为 O(节点数)，只在设置了预算或仍有已释放段落时进行。
- 样式组边界：`State` 的局部外观表 `decorations` 收为 crate 私有，局部样式只经 `State::set_style`（及 `edit_style`/`set_style_field`）写入并按控件类型的 `accepts` 校验，字号与字体只经 `set_font_size`/`set_font` 写入并要求文字控件；`State::font` 读取局部字体。经 `Node::change` 拿到 `&mut State` 的代码因此也不能给标签设光标色（`aegle-widgets/tests/appearance.rs`），类型化句柄只是把同一检查提前到编译期。

## 可运行的组合

```sh
cargo run -p aegle --example hello --release
cargo run -p aegle --example controls --release
cargo run -p aegle --example hello_markup --release
cargo run -p aegle --example markup_controls --release
cargo run -p aegle --example components --release
cargo run -p aegle-render-vulkan --example geometry --release -- target/aegle-vulkan.ppm
cargo run -p aegle-render-vulkan --features text --example vulkan_text_scene --release -- target/aegle-vulkan-text.ppm
cargo run -p aegle --example widgets --release
cargo run -p aegle --example scrolling --release
cargo run -p aegle-widgets --features motion --example standalone --release
cargo run -p aegle-widgets --example custom_control --release
cargo run -p aegle-layout --example retained --release
cargo run -p aegle-render-software --example software_scene --release
cargo run -p aegle-render-software --features text --example text_scene --release
cargo run -p aegle-render-software --features text --example editor_scene --release
```

hello 是 7 行 Rust 加 1 行文档注释的完整应用；hello_markup 为 4 行 Rust（含引入内置元素的 `use aegle::prelude::*`）、4 行标记加 1 行文档注释。controls 与 markup_controls 用相同界面演示跨控件回调、CJK 编辑、主题和关闭窗口，均使用系统字体。layout 与三个 renderer 示例没有窗口。形状示例将保留树的 Taffy 结果接到局部 Scene；首次建立 12 个记录，仅改按钮背景时重建 1 个记录，输出 `target/aegle-software.png`。

文字示例将 Paragraph 保留在同一棵树的节点中，以 Taffy 测量回调换行，并按最终布局宽度录制字形。真实显示拉丁文字、中文、日文、韩文及裁剪，输出 `target/aegle-text.png`；不是可交互控件或 GUI Hello world。测试字体共约 21 KiB，仅供测试/示例，附 OFL 原始声明和重建脚本。

`aegle-widgets` 的 standalone 示例不经 facade 和原生窗口，只用 aegle-ui、aegle-widgets、aegle-theme、aegle-motion 与软件 renderer：模拟点击、按 16 ms 推进弹簧动画到结束（约 1 s），写出 `target/aegle-standalone.ppm`，已目视检查焦点环、禁用按钮与位移后的 CJK 标签。custom_control 示例只依赖 aegle-ui 实现评分控件，指针与方向键的变化依次报告为 `[5, 4, 3, 1]`。

编辑示例输出 `target/aegle-editor.png`：同一 Editor 先录制选区、预编辑和光标，再提交中文、录制结果，最后撤销/重做并检查已提交值。它以程序调用模拟输入，不代表已经连接真实输入法。

## 已知取舍

- 公开错误为 `Box<dyn Error>` 包裹各模块的类型化错误，用 `downcast_ref` 区分，不携带节点身份；模块错误枚举标 `#[non_exhaustive]`，`aegle-gpu::Error` 除外（后端须逐项映射）。
- `Element`/`State` 的大部分字段公开，是控件库的创作面（`aegle-widgets` 依赖）；局部外观表已收为私有，样式组在 `State::set_style` 处强制（见上文），其余字段（树、焦点、扩展数据等）未收窄，`Node::change` 交出的 `&mut State` 仍能直接改它们。文字读写（`State::text`/`set_text`）、事件处理器注册与排队（`State::on_action`/`queue_action`）也在这一层，由类型化句柄包装，不在通用 `Node` 上。
- 捕获/冒泡监听器在默认行为之前同步运行（与 DOM 一致），控件动作处理器（`on_click` 等）仍在输入批次之后排队运行；控件库之间的协作仍经 `Hooks`，它们属于默认行为，`prevent_default` 一并跳过。
- 空闲文字回收按窗口执行：超出预算时只有正在刷新的窗口回收自己最久未显示的段落，不是跨窗口的全局 LRU；预算计文字字节，不是排版的实际分配。
- 可清除的属性用一个 `impl Into<Option<T>>` setter 设置与清除。`Option<&str>` 参数不再自动解引用 `&String`（写 `text.as_str()`）；皮肤是函数指针，`set_skin` 仍要写 `Some(skin)`。
- 句柄操作不返回 `Result`：句柄失效、在绘制与钩子期间使用、参数不合法都是调用方的程序错误，以 `UiError` 的消息 panic；可能比控件活得久的回调（后台代理、桌面服务事件）需先检查 `is_alive()`。`Result` 留给平台、加载与应用代码可能失败的操作；处理器可返回 `()` 或 `Result`，错误默认不结束原生 App。代价是 panic 处没有恢复路径：程序拿到失效句柄时只能通过 `is_alive` 预先判断。
- `aegle-loader` 对 `aegle-app` 的依赖是可选 feature，app 不依赖 loader。
- GPU 多窗口只共享实例/设备/管线，图集按窗口独立。
