# 资源预算与性能策略

Aegle 的资源优化优先级为：**先满足交互延迟，再依次降低空闲 CPU/唤醒、常驻 RAM、发布包体积，最后追求额外帧吞吐**。

---

## 一、 工程目标与实测数据

| 项目 | 目标门槛 | 实测口径与证据 |
|---|---|---|
| **静止主动唤醒** | 0 次/秒 | 无活动动画或外部事件时，事件循环完全挂起在系统调用上；实测 5 秒内消耗 0 CPU ticks |
| **静止 CPU 占用** | 单核平均 ≤ 0.5% | 连续 30 秒静止状态下实测 CPU 占用趋近于 0 |
| **首帧启动时间** | 热启动 ≤ 200 ms，冷启动 ≤ 600 ms | 包含系统字体发现，系统文字栈首次加载约 0.75 ms |
| **最小 Hello World 包体** | ≤ 8 MiB (Release, Strip, LTO) | **Linux SDL3 默认构建：1.54 MiB**；Linux Wayland 原生构建：2.50 MiB；`ldd` 仅依赖 libc/libm/libgcc |
| **100 控件 CJK 场景常驻 PSS** | ≤ 48 MiB | 包含字形缓存、布局树与双缓冲 SHM 映射 |
| **显式 GPU 设备内存** | ≤ 16 MiB (800×480) | Vulkan 默认 `memory_budget` 16 MiB（含图集、attachment 与上传缓冲） |

---

## 二、 内存与缓存上限配置

为了在低资源硬件（如 512 MB～1 GB ARM64 设备）上稳定运行，所有主要子系统均设有明确的可配置上限，杜绝无界泄露：

| 缓存子系统 | 默认上限 | 淘汰与回收策略 |
|---|---|---|
| **CPU 字形位图 (`GlyphCache`)** | 2 MiB / 4096 条目 | LRU 淘汰，命中不分配；未命中时按需调用系统字形光栅器渲染 |
| **Vulkan 设备内存** | 16 MiB (`Options::memory_budget`) | 超限返回 `Error::Budget`；图元每 16,384 个自动分段提交 |
| **wgpu 图元与图集** | 1024² 灰度/彩色图集 | 超大图像/路径 mask 分配独立临时纹理，使用两帧后自动释放 |
| **CPU 软件裁剪 Mask** | 可配置 (`mask_budget`)，默认不限 | 仅有形状/裁剪时按最深 clip 链深度分配（最多 8 层），同尺寸后续帧复用 |
| **未显示段落文字缓存** | 可配置 (`TextSystem::set_idle_budget`) | 超预算时按最久未显示顺序释放视口外段落的排版分配，重新进入视口时按需恢复 |
| **文本编辑器历史撤销栈** | 1 MiB (`Editor`) | 仅存储连续操作的 UTF-8 差量；单次超限安全淘汰最旧条目 |
| **离屏图层与模糊池** | 最多保留 8 张同尺寸备用 | 超出特效预算时自动跳过背景模糊（计数 `skipped_blurs`），不导致崩溃或图元丢失 |

## 三、 零开销与无轮询机制

1. **帧驱动 vs 轮询定时器**：
   * 界面仅在有明确状态修改、输入或活动动画播放时请求重绘。
   * 无活动动画时，主循环交还给平台的阻塞等待（Linux `epoll` / SDL `WaitEvent` / Win32 `GetMessage`），完全杜绝无意义的周期性轮询。
2. **局部增量更新 (Dirty Pipeline)**：
   * 仅颜色/透明度变动只打 `PAINT` 标记，跳过 Taffy 布局重新计算。
   * 仅光标闪烁或选区变动只更新已排版段落的绘制记录，不触发文字重新成形（Shaping）。
   * 滚动操作仅累加变换偏移并提交裁剪几何，直接复用已有成形和绘制记录。
